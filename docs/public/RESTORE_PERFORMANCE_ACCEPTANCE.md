# 还原性能验收

性能比较必须固定源 ZIP、字体、Figma 版本和空白目标。每次记录源 SHA-256、页面数、源记录数、图片资源量、实际创建次数、版本和降级结果；不要只比较进度百分比。

## 记录阶段

分别记录读取、校验、图片处理、创建节点、属性应用、布局后处理及收尾。区分 UI 准备、导入主线程耗时和活动总耗时；阶段可能嵌套或并行，不能简单相加当作总耗时。预览等待时间也应单列。

## 比较方法

1. 基线和候选使用独立空白目标，不覆盖已确认成功的文件。
2. 使用同一小型合成用例和同一较大匿名样例，记录每页及整场耗时。
3. 同时核对页面顺序、图层、图片、组件关联、实例覆盖、自动布局、样式及降级结果。
4. 比较峰值内存、进度连续性和实际创建次数；没有真实测量时不宣称百分比提速。

当前还原以约 50ms 连续执行预算检查让出执行权，按页/分块处理；布局阶段按候选队列运行，避免重复全页扫描。组件与图片身份在源文件会话中共享，批次不变成独立迁移包。

## 失败条件

丢层、丢引用、压平为图片、隐去降级、复用错误组件、重复创建已成功页面，均不能以速度改善抵消。中断仍应保留有效内容并明确标识 completed/partial/pending；不要把“保留了一部分”计为完整成功。
