# 缓存来源与图片校验

缓存路线只处理用户明确指定的源文件，不枚举未授权的团队文件，也不依赖逐图层 GUI 遍历。源链接负责定位，数据来自本地已有快照；工具应报告快照时间与来源证据。

## 文档来源

将源 ID、精确文档路径、元数据身份及文档 SHA-256 对齐后才转换。压缩流截断、元数据冲突或缺少身份信息时停止该源，不生成冒充完整的 ZIP。刷新画布后应重新读取并校验快照，不自动清理用户缓存。

## 图片

- 从原生设计记录中提取精确资源路径，不使用缩略图、不猜 CDN 地址，不为缺图补造视觉内容。
- 资源别名和同名文件需要保留精确身份；按已取得的图片字节计算哈希，避免不同图片被错误合并。
- 普通图片用 Pillow 检查；HEIC/HEIF 使用随插件依赖提供的本地解码能力。依赖及许可见接收插件 notices。
- 探测与转换使用受限并发，同一资源的在途任务和结果复用。校验缓存绑定源哈希及校验策略，策略变化后重新检查。
- 下载/解码/填充失败要隔离并记录缺失或降级，不能静默删除整层其他可用填充。

设计 ZIP 输出后独立检查目录结构、CRC、页索引、组件引用、资源引用及文件哈希。检查通过只说明这些结构/字节条件满足，不证明字体、渲染或最新云端版本相同。

测试图片应由代码生成或来自许可明确的最小夹具；不要提交真实设计缓存、原始业务图片或含签名参数的请求地址。
