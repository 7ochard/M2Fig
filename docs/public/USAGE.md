# M2Fig 使用说明

M2Fig 将一个 MasterGo 源文件转换成一个独立 v2 设计 ZIP，再由 Figma 开发插件恢复为可编辑页面与本地资源。它是修改版迁移工具，不是 MasterGo 或 Figma 官方产品。

## 准备

1. 按仓库根 README 完成运行环境安装和本地初始化；桌面导出目前面向 Windows。
2. 在已登录的 MasterGo 桌面客户端中打开源文件，等待画布完整加载。本地路线读取客户端缓存快照，链接只负责定位文件，不代表能直接从云端下载最新全文。
3. 在 Figma 中准备与源文件同名的 Design 文件。首次运行通过“Plugins → Development → Import plugin from manifest…”选择接收插件目录的 `manifest.json`。

## 导出与导入

1. 启动 M2Fig，输入 MasterGo 文件链接，每行一个；选择保存目录后开始导出。
2. 每个源文件单独产生同名设计 ZIP。品牌目录仅用于归档，不生成品牌总 ZIP，不覆盖已有同名未知文件。
3. 在对应的 Figma 文件里运行 **M2Fig（本地 r4）**，选择设计 ZIP。ZIP 导入默认开启，也可在“实验室”调整。
4. 默认全选页面导入；只迁单页时明确勾选该页，所需跨页主组件会作为依赖保留。
5. 检查完成报告和画布，再保存本地迁移记录。

插件安装 ZIP 和设计数据 ZIP 用途不同。安装包应先解压后注册 manifest；设计 ZIP 交给插件读取，无需重新压缩或解压。也可以直接导入受支持的原生 `.mg`。

## 结果与故障

- 完成报告区分设计页、依赖组件、源记录和实际创建次数，并列出缺字体、缺组件及其他降级。
- 导入中断后保留已完成页、部分页及有效节点。核对部分保留页后，再选择未开始页继续；不要不加核对地整文件重导。
- 部分保留不等于整文件成功；成功提示也不能替代对组件关联、覆盖值、自动布局、图片和样式的检查。
- 新安装字体可在实验室刷新。字体未安装或源数据缺失会影响还原，不保证逐像素一致。
- 桌面 EXE 不应脱离 README 指定的工程和运行时单独搬移；移动后重新初始化配置。

第一版不迁移变量绑定和原型交互。外部库组件重建为本地组件，不保留远程库关联。
