# M2Fig 整文件迁移 SOP

## 文件边界

一个 MasterGo 源文件对应一个独立 v2 设计 ZIP 和一个同名 Figma Design 文件。品牌或项目文件夹仅用于归档，不合并成品牌总 ZIP。默认整文件迁移，单页需明确指定；保持可恢复图层可编辑，不通过整页截图压平来提速。

## 执行

1. 准备源名称、源链接和本地保存目录；需要续作时先读该源已有结果。
2. 在已登录 MasterGo 桌面客户端打开源文件并等待加载。通过桌面 M2Fig 导出，或使用原生 `.mg`/备用发送插件。
3. 核对源身份、快照时间和独立 ZIP 校验报告。每个源的 ZIP、哈希和诊断分别保存，设计文件不提交到代码仓库。
4. 在 Figma 准备同名 Design 文件，运行本地接收插件。核对源名称、当前标题与 fileKey，选择正确的设计 ZIP。
5. 全文件导入默认选择全部页面；单页导入包含必要组件依赖。无需单独拆分批次或打包同一品牌全部设计。
6. 记录实际目标、页面数、依赖、源记录/创建次数、耗时、降级及用户验收结论。

## 完成与续作

核对可编辑文本、图片、真实组件关联、实例覆盖、自动布局和样式绑定。结构校验和截图都不能独立替代完整检查。

中断后保留有效内容，分别核对 completed/partial/pending。续作跳过已确认成功项；部分页先人工检查，不直接重复整场导入。不要删除已成功内容或把“保留了部分页面”标成完整成功。

## 已知边界

链接不是已验证的直接云端全文下载接口，缓存也不保证最新。字体、源缺失数据及渲染差异必须在结果中说明。第一版不迁移变量绑定、原型交互，也不保留外部库远程关联。工具无法处理的输入保留最小匿名问题样例再反馈，不上传原始业务文件或凭据。
